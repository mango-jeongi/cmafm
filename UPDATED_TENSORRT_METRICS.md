# Updated Jetson TensorRT Metrics Report

## What is directly supported by saved evaluation artifacts

The accuracy values below come directly from the saved TensorRT evaluation artifacts. The runtime values in this table are the historical evaluator measurements and are retained for traceability; they were not regenerated by the latest 100-frame dashboard run.

| Dataset | Images | mAP@0.5 | mAP@0.5:0.95 | Mean precision | Mean recall | Historical TRT inference* | Historical GPU NMS** | Derived inference + NMS |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| M3FD validation | 840 | 85.60% | 56.62% | 89.00% | 79.91% | 70.19 ms / 14.25 FPS | 4.93 ms | 75.12 ms / 13.31 FPS |
| FLIR Aligned official test split | 1,013 | 89.67% | 53.97% | 87.30% | 82.16% | 47.83 ms / 20.91 FPS | 5.24 ms | 53.07 ms / 18.84 FPS |

\* “TRT inference” includes two host-to-device input transfers, TensorRT execution, device-to-host output transfer, stream synchronization, and a host copy. It excludes image loading, resizing, NMS, box scaling, drawing, and rendering.

\** The historical GPU/PyTorch NMS timer did not explicitly synchronize CUDA around NMS. Treat these NMS values, and the derived combined values, as provisional rather than publication-quality measurements.

Both accuracy evaluations used:

- TensorRT FP16
- Batch size 1
- 640 × 640 model input
- Confidence threshold 0.001
- NMS IoU threshold 0.6
- GPU/PyTorch NMS

## Newly corrected 100-frame video runtime

The latest dashboard run used the intended timing sequence:

1. Preprocess the first real RGB/thermal frame.
2. Run 5 TensorRT warmup passes and discard them.
3. Immediately record the next 100 sequential video-frame inference measurements.
4. Exclude preprocessing, NMS, drawing, video decoding, and video encoding from the displayed TensorRT latency.

| Workload | Backend | Precision | Input | Warmup | Timed frames | TRT inference* | Approximate reciprocal rate | Observed chart range |
|---|---|---|---:|---:|---:|---:|---:|---:|
| Paired FLIR demonstration video | Jetson TensorRT | FP16 | 640 × 640 | 5 discarded passes | 100 | approximately 48–50 ms/frame | approximately 20–21 FPS | approximately 37–59 ms |

The new run no longer shows the approximately 80–100 ms cold-start spikes seen at the beginning of the earlier dashboard run. Its latency is visually stable from the first recorded frame and is consistent with the historical FLIR evaluator mean of 47.83 ms.

The approximate values above were read from the dashboard chart. The completed run did not export its numerical per-frame samples, so they must not be reported as exact means, standard deviations, or percentiles. Reciprocal latency (`1000 / mean latency`) is engine-rate potential, not measured end-to-end video throughput.
